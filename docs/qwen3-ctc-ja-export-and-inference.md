这份文档写给做 ONNX 导出、量化、llama.cpp 接线和 benchmark 的那条线。

`evaluate.py` 已经是 `cfg.get("ffn_hidden") or args.ctc_ffn`，导出脚本照抄这个写法。

`config` 里的 `encoder_dim` 这轮是对的（2048）。r1 那个老 checkpoint 写着 1280 是
陈旧元数据，别拿它当参考。

## 2. 建议发 `v1-ja`，不是 `v2-ja`

理由：

1. **日语只差 0.43pp**（27.69% 对 27.26%），而这 0.43pp 相对 12–14pp 的改善可以忽略。
2. **中文是四个模型里最好的**（5.22%），而且相对自己的基线是真实改善，不是噪声。
   CapsWriter 是中文听写工具，中文是主场景。
3. **小 17%**：48.3M 对 58.2M，int4 导出后的部署件更小，加载更快。

原来 v1 的定位是「中文优先但日语弱」，现在日语这个短板补上了，没有理由再选 v2。

如果要同时发两个，v2-ja 可以作为「多语种均衡版」，但差异小到不值得让用户做选择。

## 3. 训练侧改了什么（影响你复现）

这一轮往 `prepare_manifests.py` 和 `train_ddp.py` 打了几个补丁，提交在
`f2cd4b6` 和 `d0b1c51`。和导出无关，但如果你要重训或复现，这几条是必需的：

- **Common Voice 的 TSV 解析少读了 8.5%。**`csv.DictReader` 默认的 quotechar 会把
  含半角 `"` 的句子和后续若干行并成一行。日语 validated 因此少读 25,613 行
  （300,077 → 274,464，38.0 小时），而日语恰好是最缺数据的语种。已加
  `quoting=csv.QUOTE_NONE`。yue/zh-HK/zh-TW 恰好没触发所以一直没暴露。
- **`--resume-lr`**：`scheduler.load_state_dict` 会把 `base_lrs` 一起恢复，所以接续
  训练时 `--lr` 是完全无效的。调度器是
  `0.5*(1+cos(pi * step / max_steps))`，分母不减 warmup，接续时 step 已经很大，
  同一个峰值在不同 resume 点给出的实际 LR 能差好几倍。
- **分片键从 `hash()` 换成 `zlib.crc32`**：内置 `hash` 对 str 是带 PYTHONHASHSEED
  随机化的，续传永远命中不了，中断重跑等于全量重解并留下孤儿文件。

143.4 GB，把原始电视字幕和 Whisper 转写做 WER ≤ 10% 的一致性过滤后保留的部分
（条数保留 33.7%）。**它的实测时长是 1,253.4 小时，不是按体积比例外推的 2,050 小时**

训练配方是从各自基座接续 **1 个完整 epoch**（32,547 步，batch 32×8=256/步），
起始 LR 1.1e-4 余弦退火到 0，其余 26 条 manifest 一条不删。

## 5. 还没做的事

**FLEURS 日语没测过。** 这是发 PR 前最需要的一个数。

现在手上的 27.26% / 27.69% 是 ReazonSpeech 广播语音，自发口语、领域宽；
Fun-ASR 那个 17.0 是 FLEURS 朗读语音。**两个数不可比**，不能拿来说
「我们和 Fun 拉不开差距」。要给作者一个能对话的数字，必须在 FLEURS ja_jp
的官方 test（650 句）上跑一遍，和 GLM 那张十一语种表同一个口径。

口径要求见 r2 那份文档的「用 FLEURS 测的话，几个口径问题」一节：归一化两边一致
（NFKC + 小写 + 去标点 + 折叠空白），并且要说明训练集里没掺 FLEURS。

**W&B 上的轨迹**：project `qwen3-asr-ctc`，run 名 `qwen-asr-ctc-v1-ja-enhance`
和 `qwen-asr-ctc-v2-ja-enhance`。周期性 checkpoint 每 4000 步传一次，
`best`/`final` 始终传，可以直接从 artifact 拉权重，不必登 npu107。

## 6. 几个仍然有效的老坑

这些在 r2 那份文档里都写过，这里只列清单提醒，细节看原文：

- 帧率 **13 fps**（76.9 ms/帧），不是 GLM 的 50 fps。官方长度公式是
  `... + (mel_len // 100) * 13`。
- 编码器吃的是时间维拼接的 2D 张量 `[128, ΣT_mel]` 加 `feature_lens`，
  返回扁平的 `[ΣT_out, 2048]`，不是常规的 batch 维。
- attention mask 补丁必须打，导出后要用**不同长度**验证，只用一个长度测不出问题。
- 反词表化必须走字节再解码，不能拼字符串——紧凑词表是从 Qwen3 的
  byte-level BPE 映射来的。
- 多卡评测会在最后一次 `all_gather_object` 上死锁（2026-09-07 在 8 卡和 6 卡上各
  复现一次，表现是单张卡 AICore 100% 空转、其余 0%，三张卡单独跑 matmul 都健康，
  所以不是硬件）。测试集不大的话用 `NPROC=1`，5,263 句只要 49 秒。
